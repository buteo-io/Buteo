# Security Policy

We take security seriously. If you discover a vulnerability in Buteo, please report it to us privately so we can address it before public disclosure.

---

## Supported Versions

We actively support and patch security issues in the latest major release of Buteo:

| Version | Supported |
|---------|-----------|
| >= 1.0.0| ✅ Yes     |
| < 1.0.0 | ❌ No      |

*Please update your deployment to the latest version to ensure security patches are active.*

---

## Reporting a Vulnerability

**Please do not open public GitHub issues for security vulnerabilities.**

Instead, report vulnerabilities through **Email:** Send details to **security@getbuteo.com**.

### Please include:
- A clear description of the issue.
- Step-by-step instructions or proof-of-concept (PoC) code to reproduce the vulnerability.
- Potential impact (e.g., privilege escalation, remote code execution, data exposure).
- Affected components (e.g., API server, ingest server, frontend).

---

## Our Response Process

1. **Acknowledgment:** We will acknowledge receipt of your report within **48 hours**.
2. **Triage:** We will investigate and assess the vulnerability's impact.
3. **Remediation:** We will develop a fix and test it across supported versions.
4. **Disclosure:** Once the fix is released, we will publish a security advisory acknowledging your contribution (unless you prefer to remain anonymous).

We aim to resolve all high-severity issues within **14 days** of reporting.
